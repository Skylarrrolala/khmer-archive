# Verified content package — Khmer Traditional Cakes & Snacks (នំខ្មែរ)

Prepared 21–22 November 2026 on `feature/national-museum-redesign`. Nothing here
has been applied to production.

## What is in this folder

| File | What it is |
| --- | --- |
| `research-num-ansom.md` | Evidence register for Num Ansom Chek and Num Ansom Chrouk |
| `research-num-korm-num-bot.md` | Evidence register for Num Korm (num kom) and Num Bot |
| `research-num-plae-ai-num-kroch.md` | Evidence register for Num Plae Ai and Num Kroch |
| `research-num-kong-num-akor.md` | Evidence register for Num Kong and "Num Kor" (documented as Num Akor Thnot) |
| `production-snapshot-2026-11-21.json` | The seven researched rows exactly as read from production (public, published-only API) on 21 November; re-read unchanged on 22 November |
| `preflight-content-update.sql` | **Read-only** check: for each row, whether it is ready for the update or the rollback |
| `proposed-content-update.sql` | **Unexecuted**, guarded update: snapshot text → reviewed `checked` text |
| `rollback-content-update.sql` | **Unexecuted**, guarded reversal: reviewed text → snapshot text |

The last three are generated by `scripts/generate-content-update.ts`; never edit them by hand.

Each register covers, per dessert:
- identity and naming;
- a claim-to-source table (SUPPORTED / PARTLY / CONTRADICTED / UNSUPPORTED),
  each claim with a short verbatim quote;
- full citations rated strong / moderate / weak;
- the research draft narrative;
- the claims still unresolved.

The research was done by four research agents. Every source they cite was
opened; sources they could not open are listed separately and not cited. The
drafts in the registers are the agents' versions; the reviewed text is the
`checked` text in `lib/exhibit-records.ts`.

## How it reaches the site

**The database is the only source of displayed text.** `lib/exhibit-records.ts`
holds, per published exhibit, three things: its references and what each
documents, the public "Not yet verified" list, and `checked`. `checked` is the
exact name, occasion and description the references were checked against.

A record attaches to a row only while the row matches `checked` exactly:
- If a contributor edits their entry, its references detach automatically.
- Until the content update is applied, the researched rows keep today's text
  and today's disclosures.

So the page, the occasion shown and search always read the same fields.

- `told_by` still holds `[SOURCE PENDING …]` (or "Family"). The page presents
  written references as written research and says no oral source has been
  recorded. Written research does not replace a named, consenting person.
- Num Kroch belongs to a contributor. Its text stays theirs; its references
  were checked against that text and detach if it changes.
- Records only decorate rows the published-only query returns.

## Coordinated release (needs your approval)

The code and the data can go out **in either order**, and both orders are safe.

| State | What visitors see |
| --- | --- |
| Code deployed, update not applied | Today's text. The seven researched rows show "Source pending verification" as now. Num Kroch shows its references. |
| Update applied | The reviewed text, its references, "Not yet verified" lists, the corrected Num Akor Thnot name. Search matches what each page shows. |
| Rollback applied | Byte-for-byte today's database. The records detach by themselves. |

### What the scripts guarantee

The update and the rollback are each all-or-nothing. Each runs one
transaction with one guarded block, which:

1. **locks** the review history and the seven rows, then records the
   history:
   - the review history takes a SHARE lock: other sessions can read it,
     but no write can land until the transaction ends;
   - the seven rows are locked against edits;
   - a full copy of the history is taken (every column of every row);
2. **refuses** unless all seven exist and each holds exactly its expected
   starting state:
   - Khmer name, English name, occasion and description;
   - source marker, photo and `created_at`;
   - no owner, and published;
3. **updates** under that same full condition and requires **exactly 7**
   changed rows;
4. **re-verifies**:
   - **identity:** exactly the seven target ids are still present, and every
     planned id is checked from the plan side, so a missing or re-identified
     row cannot drop out of the check;
   - **values:** every resulting value is exact, with the protected fields
     unchanged;
   - **history:** the review history is identical in content, compared
     with `EXCEPT ALL` in both directions. That comparison ignores row order
     and treats NULLs as equal, so a retimed, edited, added or removed row
     is caught even when the count is unchanged;
5. **commits only if every check passed.**

Any failure raises an error inside the block, so nothing at all is written.
No intervening edit is ever overwritten: a row someone has changed since the
snapshot stops the whole update, and a row changed since the update stops
the whole rollback. The error names the affected dessert.

A passing dry run is **not** evidence that production is still unchanged.
The scripts check the live rows themselves at run time, and the preflight
lets you see the state before running anything.

### Execution sequence (each step needs your approval)

1. **Deploy the code.** Safe on its own: pages keep today's text, and the
   researched references stay detached.
2. **Preflight.** Run `preflight-content-update.sql` in the Supabase SQL
   editor. It is read-only and ends with ROLLBACK. Continue only if all
   seven rows show `present = true` and `ready_for_update = true`. If any
   does not, stop: that row was edited after the review and must be
   re-checked, then `checked` updated and the SQL regenerated.
3. **Update.** Run the whole of `proposed-content-update.sql`. Success
   prints "Content update verified: 7 rows changed" and reports the seven
   rows. Any "aborted" message means nothing was written.
4. **Check the live site.**
   - Search "akor" finds Num Akor Thnot.
   - The researched records show their references.
   - Num Kroch is unchanged.
5. **Rollback, only if needed.** Run the preflight again: all seven must
   show `ready_for_rollback = true`. Then run the whole of
   `rollback-content-update.sql`. It refuses if anything was edited after
   the update, so a later correction is never thrown away.

### Changing the reviewed text later

Edit `checked` in `lib/exhibit-records.ts`, then run
`node scripts/generate-content-update.ts` and commit the regenerated files.
`tests/exhibit-records.test.ts` fails if the committed SQL differs from the
generator's output. Before running anything, re-run
`bash scripts/test-content-update.sh`.

Do not run `supabase/seed.sql`. It deletes and re-creates ownerless rows,
which changes their ids and detaches every record.

## Checks run

- **Sources re-read directly.** Load-bearing claims were checked in the
  sources themselves, not only in the agents' reports:
  - Headley on num bot;
  - the Phnom Penh Post (ANN) wrapped-cakes feature;
  - the Chuon Nath entries for អន្សម, នំ, ផ្លែអាយ, កើតក្តី and អាកោ;
  - SEAlang's "Nothing found" for នំកោ;
  - Cambodianess on num ansom and num kang;
  - the 2005 royal decree on the national tree.
- **Links.** All 37 reference URLs returned HTTP 200 on 21 November 2026.
- **Unit tests** (`tests/exhibit-records.test.ts`) reject:
  - references presented for edited text;
  - a contributor's photo being replaced;
  - drift between the SQL and the records;
  - bracketed markers, first-person or family testimony in researched text;
  - text over migration 0002's limits.
- **Release dry run** in a throwaway Postgres built from migrations
  0001–0008. It was seeded with production's eight published rows exactly as
  read through the public API, with a stand-in owner for Num Kroch. The
  app's own search query (name or occasion, `ilike`) was run as `anon`, so
  RLS applied.

  | State | Records attached | Search "akor" | Search "weddings" |
  | --- | --- | --- | --- |
  | Before | 1 of 8 (Num Kroch) | nothing | only Num Korm, from its old occasion |
  | Update committed | 8 of 8 | Num Akor Thnot (and "អាកោ") | the three records whose occasion says weddings |
  | Rollback committed | 1 of 8 | nothing | not re-run |

  After the update, "religious" returned nothing, consistent with the
  occasions now shown. Also unchanged by the update:
  - Num Kroch;
  - the 7 source markers, 8 published statuses and 8 photos;
  - the review-history count (8 before and after).

  After the rollback, the whole table was byte-identical to before (md5).
- **Refusal scenarios** (`bash scripts/test-content-update.sh`, disposable
  Postgres): 39 passed, 0 failed. Each refusal passes only if the SQL fails
  with the expected reason and every entry and review-history row is
  byte-identical to just before it ran. The scenarios cover:
  - the normal update and rollback;
  - a second run of either script;
  - each kind of drift before the update, and each kind of edit between
    update and rollback;
  - a missing row;
  - a changed owner or status;
  - only 6 rows changing;
  - a protected field changing underneath;
  - in both directions, injected triggers that change a target's id, or
    retime, insert or delete a review-history row;
  - concurrency: a history write and a target-row edit from a second
    session both wait on the update's locks.

  Run against the SQL at `6f1c177`, the same suite reproduces the re-audit
  findings: the id change and the history retime committed in both
  directions, and the concurrent history write went through.

## Editorial decisions made on top of the research

- **Num Plae Ai.** The "husband-killing cake" story is dropped as fact: it
  appears only in English-language blogs since 2018 and in no Khmer source.
  - The record now gives the names and elders' tales recorded by Chuon Nath:
    num bompuon skor, the King Ang Duong custom, and num kaet kdei.
  - In that tale the syrup squirts into the other man's *eye*. The research
    draft said "face" and was corrected against the dictionary.
  - The occasion is "Everyday snack": no festival use is documented.
- **Num Kor.** នំកោ is not attested in any dictionary consulted. The update
  renames the record to the documented cake, num akor thnot (នំអាកោត្នោត).
  Headley also records a vulgar slang sense of bare នំអាកោ, which is one more
  reason to use the full name.
- **Num Korm.**
  - "Toasted" sesame was removed: the only recipe source names black sesame
    and does not say toasted.
  - "Remains easy to find" is reduced to what the sources show: it is sold in
    markets and by makers.
- **Num Kong.** "An everyday sweet rather than a festival dish" was an
  exclusion resting on absence of evidence. It now says only that the
  sources consulted do not mention festival or ceremonial use.
- **Num Ansom Chek.**
  - The male/female and mother/father readings are attributed to the
    historian and officials quoted, not stated as fact.
  - Home-making being more common in the countryside is attributed to the
    maker who said it.
- **Num Ansom Chrouk.** It stays in the collection and is labelled savoury.
  Chuon Nath counts num "among snacks and sweets of every kind", and
  Cambodianess describes savoury and sweet fillings. The collection was
  renamed Khmer Traditional Cakes & Snacks (នំខ្មែរ) on 22 November so that
  savoury num belong by name. The record's reviewed text now says it belongs
  "in a collection of Khmer cakes and snacks", and the generated SQL was
  regenerated to match.
- **Num Bot.** The text keeps to what the dictionary and Khmer press record:
  a salted mung-bean filling and flat parcels.
  - Its sweetness, name origin and regions are listed as unverified.
  - The record says the photograph may show num kom parcels.
